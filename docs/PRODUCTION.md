# Продакшен

Бот: `@dobrolapzoo_bot`. Код, каталог, фото и реквизиты берутся из текущего развёртывания. Секреты находятся только в серверном `.env` и `secrets/`.

Рабочая таблица подтверждена владельцем: текущая таблица с названием «Размещение добролап — ТЕСТ» используется как продакшен. Доступ через сервисный аккаунт, запись включена. Название таблицы не меняется.

База продакшена: `data/production/app.db`; FSM: `data/production/app_fsm.db`. Данные старого тестового бота сохраняются отдельно. Одновременно опрашивается только продакшен-бот.

## Первый вход владельца

На сервере заданы `OWNER_BOOTSTRAP_USERNAME=alenrethf` и пустой `OWNER_CHAT_ID`. Когда этот аккаунт впервые напишет боту в личном чате, числовой Telegram ID сохраняется в `data/production/owner_binding.json`. Вход через `/start` сразу открывает панель владельца. При обычном сообщении бот сообщает о привязке и предлагает `/start`.

Привязка действует сразу для заявок, административных действий и фоновых уведомлений, сохраняется после перезапуска. После первой привязки изменение username не передаёт права другому аккаунту. Для ручной настройки можно задать числовой `OWNER_CHAT_ID`; он имеет приоритет. Файл привязки относится к конкретному bot ID.

До первого входа владельца заявки сохраняются, но уведомления владельцу недоступны. Оператор может увидеть сохранённые заявки через панель после входа.

## LLM

При миграции на сервере нет LLM API-ключа; `LLM_ENABLED=false`. Работает предусмотренный fallback. Для включения реального LLM нужны действительные `LLM_API_KEY` и `LLM_MODEL`. Цены, занятость и подбор помещений от LLM не зависят.

## Откат

Путь к резервной копии конфигурации и баз хранится на сервере в `/root/dobrolap-production-migration-backup-path`. Восстановить `previous.env` из этой копии в `.env`, затем выполнить `docker compose up -d --no-deps bot`. Копию продакшен-базы сохранить перед откатом. Резервные копии и файлы с секретами не добавлять в Git.
